# Основные правила разработки

**Проект:** MeterVision
**Тип проекта:** учебный (командный проект студентов)
**Состав команды:** 7 человек

Документ описывает обязательные для команды инструменты и правила работы с ними. Все участники должны следовать этим правилам с момента старта проекта.

## 1. Методология разработки — Agile (Scrum)

### 1.1. Общие принципы

- Работа ведётся короткими итерациями — **спринтами**.
- **Длительность спринта:** 2 недели.
- По итогам каждого спринта должно быть **работающее инкрементальное улучшение** продукта.
- Все задачи фиксируются в бэклоге до начала спринта.
- Планирование и обзор — обязательные ритуалы.

### 1.2. Ритуалы

| Ритуал | Периодичность | Участники | Цель |
|---|---|---|---|
| Sprint Planning | Начало спринта | Вся команда | Выбрать задачи из бэклога в спринт, оценить, распределить |
| Daily Standup | Ежедневно | Вся команда | Что сделано / что делаю / какие блокеры |
| Sprint Review | Конец спринта | Вся команда | Демо результата спринта |
| Sprint Retrospective | Конец спринта | Вся команда | Что получилось / что улучшить |
| Backlog Refinement | Середина спринта | Тимлид + Архитектор | Уточнение и приоритизация бэклога |

## 2. Git

### 2.1. Модель ветвления — Git Flow (упрощённый)

Используется упрощённый **Git Flow** с feature-ветками.

### 2.2. Основные ветки

| Ветка | Назначение | Кто пушит |
|---|---|---|
| `release/*` | Стабильный релиз определенной версии. Только проверенный код | Тимлид + Архитектор(через PR) |
| `rс/*` | Пререлизная версия кода. Версия из `develop` которую стабилизируем для релиза | Тимлид + Архитектор(через PR) |
| `main` | Стабильный релиз. Только проверенный код | Тимлид + Архитектор(через PR) |
| `develop` | Основная ветка разработки | Все участники (через PR) |
| `feature/*` | Ветки под задачи | Разработчики |
| `hotfix/*` | Срочные исправления в `main` | Тимлид + Архитектор + ответственный |

## 4. GitHub Projects

| Колонка | Что значит | Кто перемещает |
|---|---|---|
| Backlog | Все задачи, ещё не запланированные | Тимлид / Аналитик |
| TODO | Задачи текущего спринта | Тимлид на Sprint Planning |
| In Progress | В работе | Разработчик (assignee) |
| In Review | На код-ревью | Автор PR (автоматически при открытии PR) |
| Testing | На тестировании | QA-инженер |
| Done | Завершено | Тимлид |

## 5. GitHub Actions (CI/CD)

### 5.1. Назначение
GitHub Actions используется для непрерывной интеграции и доставки (CI/CD): автоматическая сборка, тестирование, проверка качества, публикация артефактов.

## 5.2 Требования к CI

- Все workflow запускаются автоматически на Pull Request.
- PR не может быть смержен при провале CI.
- Время выполнения CI — не более 10 минут на один workflow.
- Кэширование зависимостей (actions/cache) — обязательно.
- Секреты хранятся в GitHub Secrets, не в коде.

## 6. VSCode и расширения

### 6.1. Единая среда разработки

Вся команда использует Visual Studio Code как основную IDE(редактор кода) дополнив её необходимыми расширениями и инструментами.

### 6.2. Настройки workspace
В репозитории хранится файл .vscode/settings.json с общими настройками:
- форматирование при сохранении;
- единый размер отступа;
- линтеры;
- исключения для поиска.

### 6.3. Конфигурации запуска и отладки

В репозитории хранится файл `.vscode/launch.json` с общими конфигурациями запуска и отладки:

- **Запуск backend** — конфигурация для локального запуска ASP.NET Core с отладчиком, с возможностью автоматической сборки проекта перед запуском и открытия Swagger в браузере.
- **Запуск CV-сервиса** — конфигурации для запуска Python-сервиса напрямую или через uvicorn с авто-перезагрузкой при изменении кода.
- **Запуск мобильного приложения** — конфигурации для запуска Flutter-приложения в режимах debug, profile и release, а также для подключения к уже запущенному приложению.
- **Совместный запуск нескольких сервисов** — compound-конфигурации для одновременного запуска backend, CV-сервиса и мобильного приложения одной командой, что упрощает локальную разработку и тестирование сквозных сценариев.
