# Требование к User Flow

**User Flow** - это маршрут путешествия пользователя через экраны приложения к важной цели.

## Основные требования к структуре

- **Наличие точки входа - старта:** Четкое определение, откуда пользователь начинает путь (прямой запуск приложения, страница авторизации).
- **Одна главная цель:** Каждый отдельный сценарий должен вести к конкретному результату (вход в аккаунт, сделать снимок, отправить фотографию).
- **Точки принятия решений (ветвления):** Обязательное отображение развилок (например: «авторизован ли пользователь?», «успешный ли вход?» с вариантами «да/нет»).
- **Точка финала:** Успешное завершение задачи или тупик при ошибке с возможным возвратом назад.

## Стандарты визуализации и элементы

- **Использование стандартных фигур** (овалы - старт/конец, прямоугольники - действия, ромбы - выбор/условия).
- **Каждый шаг обозначается глаголом**, описывающим действие (например, «нажать кнопку», «ввести логин»).
- **Ошибки, отмены действий и повторные попытки** (что делать, если введен неверный пароль, не прошла оплата или прервалось интернет-соединение) должны быть учтены, но не перегружать основной путь.
