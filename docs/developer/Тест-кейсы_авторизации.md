# Тест-кейсы авторизации MeterVision

## 1. Цель тестирования

Проверить экран авторизации, валидацию полей, переключение видимости пароля, отображение загрузки и ошибки входа.

## 2. Условия тестирования

- Приложение: MeterVision, мобильный клиент Flutter.
- Экран: авторизация.
- Типы тестирования: функциональное, UI, автоматизированное widget-тестирование.
- Тестовые данные: `testuser` / `password123`.
- Серверная авторизация пока не подключена; ошибка входа моделируется приложением.

## 3. Тест-кейсы

| ID | Проверка | Ожидаемый результат | Статус |
|---|---|---|---|
| AUTH-01 | Открытие экрана | Отображаются поля логина и пароля, кнопка «Войти» | Автоматизирован |
| AUTH-02 | Пустые поля | Отображаются ошибки для логина и пароля | Автоматизирован |
| AUTH-03 | Короткий логин | Отображается ошибка минимальной длины логина | Автоматизирован |
| AUTH-04 | Короткий пароль | Отображается ошибка минимальной длины пароля | Автоматизирован |
| AUTH-05 | Видимость пароля | Переключение показа и скрытия пароля работает | Автоматизирован |
| AUTH-06 | Загрузка | После отправки допустимых по длине данных отображается индикатор загрузки | Автоматизирован |
| AUTH-07 | Ошибка входа | Отображается сообщение об ошибке авторизации | Автоматизирован |
| AUTH-08 | Повторное нажатие во время загрузки | Повторная отправка не запускается | Требует отдельной проверки |
| AUTH-09 | Нет сети | Отображается понятное сообщение о проблеме соединения | Ожидает интеграции с API |
| AUTH-10 | Сервер недоступен | Отображается сообщение о недоступности сервера | Ожидает интеграции с API |
| AUTH-11 | Успешный вход | Получен токен, открыта защищённая часть приложения | Ожидает интеграции с API |
| AUTH-12 | Хранение токена | Токен безопасно сохраняется и используется в защищённых запросах | Ожидает реализации |
| AUTH-13 | Недействительный токен | Пользователь возвращается на экран входа | Ожидает интеграции с API |
| AUTH-14 | Выход из аккаунта | Токен удаляется, отображается экран входа | Ожидает реализации |

## 4. Результаты тестирования

Запуск автоматизированных тестов из каталога `mobile/`:

```bash
flutter test
```

Последний результат: все 5 существующих widget-тестов пройдены.

Статический анализ:

```bash
flutter analyze lib test
```

Последний результат: `No issues found!` при запуске из `mobile/`.

## 5. Ограничения

Текущая реализация использует имитацию серверного запроса. Реальная авторизация, получение и безопасное хранение токена, обработка сетевых ошибок, проверка сессии и выход из аккаунта пока не подтверждены тестами.

Статус «Автоматизирован» означает, что проверка покрыта существующими widget-тестами. Остальные проверки требуют дополнительной реализации или автоматизации.
