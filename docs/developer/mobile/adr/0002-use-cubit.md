# ADR-001: Использование Cubit для управления состоянием
## Статус
Принято

## Контекст
Для работы приложения необходим менеджер состояния, который хранит данные экрана, реагирует на действия пользователя и уведомляет UI об изменениях. Без него пришлось бы вручную синхронизировать setState между виджетами, что при росте приложения приводит к сложностям.

Рассматривались: **bloc**, **cubit**.

Полноценный BLoC (события + состояния) требует значительного количества шаблонного кода. При этом приложение не является высоконагруженной системой с массовыми конкурентными потоками - большая часть состояний сводится к простым переходам: загрузка → успех / ошибка, переключение вкладок.

Cubit не использует события и меняет состояние через прямые вызовы методов, что упрощает чтение кода.

## Решение
Принять Cubit как основной инструмент управления состоянием в проекте.
