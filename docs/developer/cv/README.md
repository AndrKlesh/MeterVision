# CV-сервис. Архитектура

Документация по сервису распознавания показаний счётчиков (Python, FastAPI, OpenCV, EasyOCR). Сервис принимает фото от backend и возвращает серийный номер, значение показания и оценки уверенности.

## Источники и статус документа

| Источник | Как использован |
|---|---|
| ТЗ (разделы 5.3, 7, 9) | Требования к сервису: предобработка OpenCV, EasyOCR, постобработка, оценка уверенности по каждому полю, ≤ 5 с, точность ≥ 85% на ≥ 20 фото |
| Код `cv/` (заглушка) | **Фактическая** часть: `POST /api/ocr`, `GET /health`, интерфейс `OCREngine`, схемы ответа |
| Эталонный образец счётчика | Описание электросчётчика МИР С-04.10, на котором построен анализ сложностей и правила постобработки |
| Реальный движок (OpenCV + EasyOCR) | **Не существует.** Конвейер спроектирован с нуля |
| Ответы команды на вопросы | Решения по формату данных, поведению при ошибках, расположению документации (учтены, см. «Решено на согласовании») |

## Эталонный образец

Электросчётчик МИР С-04.10 с графическим ЖК. Крупные цифры, значение в кВт·ч, режим «Актив.эн. прям.». Серийный номер напечатан **вертикально** вдоль левого края корпуса. Сильные блики, много посторонних надписей.

Ожидаемый результат распознавания:
- `reading_value`: **50.99** (2 знака после точки)
- `serial_number`: **50794925145054** (14 цифр, требуется сверка с оригиналом прибора)

Наблюдения (подробно в [recognition.md](recognition.md#2-наблюдения-по-образцам)): точечный графический ЖК, серийный номер повёрнут на 90° и идёт вдоль края корпуса, сильные блики, много посторонних надписей и чисел.

## Архитектура в одном абзаце

Сервис остаётся тонкой FastAPI-обёрткой над абстракцией `OCREngine` (она уже есть в коде). Реальная реализация `EasyOCREngine` оркестрирует конвейер: декодирование и нормализация изображения → предобработка (контраст, блики) → поиск дисплея → распознавание EasyOCR → постобработка (чистка символов, формат числа, разделители) → оценка уверенности по каждому полю. Если значение или серийный номер не найдены, сервис возвращает ошибку `422 not_recognized`, а не `5xx` и не пустой успех. Заглушка `MockOCREngine` остаётся для разработки остальных частей.

## Принятые проектные решения

| № | Решение | Обоснование |
|---|---|---|
| 1 | Конвейер из шести этапов, каждый этап отдельный модуль | Этапы тестируются независимо, постобработку и оценку уверенности можно проверять без моделей |
| 2 | Сохраняется интерфейс `OCREngine`. Реальный `EasyOCREngine` и заглушка взаимозаменяемы | Так задумано в коде и README, контракт для backend не ломается |
| 3 | Не распознано значение или серийный номер → `422` с кодом `not_recognized`. Пользователь переснимает так, чтобы в кадр попали и экран, и серийный номер | Решение команды. Соответствует ТЗ 5.3: «осмысленный ответ, а не ошибка сервера» |
| 4 | Итеративная разработка: baseline → улучшения по метрикам датасета | Реального кода и данных нет, сложность оправдана только измерениями |
| 5 | Предобученный EasyOCR, дообучение только если точность < 85% | Сначала нужен датасет и измерение. Собранные фото используются для оценки и подбора порогов |
| 6 | Оценка уверенности отдельно по серийному номеру и показанию (расширение контракта) | ТЗ 5.3 требует оценку по каждому полю, в заглушке она одна |
| 7 | `reading_value`: строка, число знаков после точки **фиксировано для модели** (МИР С-04.10: 2), нули сохраняются | Решение команды: формат не угадывается по числу цифр, положение точки задаётся заранее. Потерянную OCR точку можно восстановить по этой позиции |
| 8 | Серийный номер: цифры, заглавные латинские буквы и дефис, 6–20 символов, цифр не меньше половины. Без кириллицы | Команда: буквы бывают, дефис добавить, кириллица не нужна. Условие про цифры отсекает буквенные обрывки названия модели (`KNQ`, `P2Z1B`) |
| 9 | Единицы измерения (кВт·ч) в ответ не возвращаются | Команда: пользователь знает, какой счётчик фотографирует |
| 10 | Цель по точности: **оба поля верны одновременно** ≥ 85% | Решение команды, уточняет ТЗ |
| 11 | Область: одна модель, МИР С-04.10 (электро). Другие типы, возможно, позже | Решение команды |
| 12 | CV **не проверяет**, тот ли это счётчик. Сервис возвращает серийный номер и значение, а привязку к прибору при необходимости определяет backend по серийному номеру | ТЗ раздел 6: прибор учёта «опционально для MVP», обязательно хранить показание и распознанный серийный номер |
| 13 | Распознавание выполняется на сервере | Так в ТЗ, подтверждено командой, см. [architecture.md](architecture.md#где-выполняется-распознавание) |
| 14 | Модели EasyOCR запекаются в Docker-образ | Сервис во внутренней сети без интернета, загрузка при старте недопустима |
| 15 | Одновременно обрабатывается ограниченное число запросов, масштабирование контейнерами | EasyOCR тяжёлый по CPU и памяти |
| 16 | Изображения не сохраняются и не логируются (кроме явного режима отладки) | Приватность, меньше рисков |
| 17 | Документация лежит в `docs/developer/`, вне папки `cv/` | Решение команды |

## Решено на согласовании

| Вопрос | Решение команды |
|---|---|
| Если серийный номер или значение не видно | Возвращаем ошибку, пользователь переснимает так, чтобы всё попало в кадр |
| Формат серийного номера | Буквы бывают, дефис добавить, кириллицы нет |
| Число знаков после точки | Фиксированное положение точки для модели (МИР С-04.10: 2 знака). По числу цифр формат не угадываем |
| Возвращать ли единицы измерения | Нет |
| Определение точности ≥ 85% | Оба поля верны вместе |
| Типы счётчиков | Только МИР С-04.10 (электро), другие, возможно, потом |
| Штрихкод как источник серийного номера | Убран из плана: на образце электросчётчика штрихкода нет (он был только на другом приборе, убранном из документации). Вернуться к вопросу, если появится прибор со штрихкодом |
| Проверка «тот ли счётчик» | В CV не делаем, прибор определяется по серийному номеру на стороне backend |
| Где выполняется распознавание | На сервере |
| Где лежит документация | `docs/developer/` |

## Открытые вопросы

| № | Вопрос | Кому | Влияние |
|---|---|---|---|
| 1 | Длина серийного номера. Допущение: 6–20 символов, по образцу 14. Уточнить по паспорту прибора | Заказчик, ML | Правила постобработки |
| 2 | Железо сервера неизвестно. Проектируем под худший случай (только CPU), замер на целевом сервере обязателен | DevOps | Уложиться ли в 4 с |
| 3 | Экран электросчётчика переключается между параметрами (на образце «Актив.эн. прям.»). CV вернёт число с экрана, режим не проверяет. Нужна ли подсказка в приложении, какой параметр показывать | Flutter, заказчик | Текст подсказки, UX |
| 4 | Подтвердить по паспорту МИР С-04.10, что в режиме накопленной энергии всегда 2 знака после точки (на образце 2). От этого зависит фиксированный формат значения | Заказчик, ML | Формат значения, восстановление точки |
