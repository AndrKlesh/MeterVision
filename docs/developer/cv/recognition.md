# Распознавание показаний

Модули: `pipeline/recognizer.py`, `pipeline/postprocessing.py`, `pipeline/confidence.py`, оркестрация в `engine/easyocr_engine.py`.

Правила и пороги ниже **стартовые**. Они выведены из двух образцов и требований ТЗ, а окончательные значения устанавливаются по результатам на датасете.

## 1. Задача

Область первой версии: одна модель прибора — МИР С-04.10 (электро). Другие типы, возможно, добавятся позже.

| Вход | Выход |
|---|---|
| Изображение JPEG/PNG одного счётчика | `serial_number`: строка. `reading_value`: строка с точкой. Уверенность по каждому полю. `bbox` для значения и серийного номера |
| Нет значения или нет серийного номера | Ошибка `not_recognized` со списком недостающих полей |

## 2. Наблюдения по эталонному образцу

Образец — электросчётчик МИР С-04.10, описанный в разделе «Эталонный образец» в [README](README.md#эталонный-образец). Таблица построена по **визуальному анализу**: OCR на нём пока не запускался. Поэтому колонка «Выводы по образцу» это ожидания и гипотезы, подтвердить которые можно только замером на датасете.

| Наблюдение | Выводы по образцу |
|---|---|
| Точечный графический ЖК, крупные цифры | Ожидаемо проще для OCR, обработка не должна ухудшать результат. Проверить |
| Число знаков после точки: 2 | Нельзя «додумывать» формат по числу цифр. Указать фиксированное положение точки для модели |
| Серийный номер вертикальный вдоль края корпуса, частично у границы кадра | Нужен поиск с поворотом на 90° и 270°. Номер может обрезаться кадром |
| Блики на стекле, закрывают часть корпуса | Предобработка бликов, см. [preprocessing.md](preprocessing.md) |
| Много посторонних надписей и цифр: `+5…90`, `2025`, `230`, `5(100)`, `A=500`, `R=500`, `ГОСТ`, `Bluetooth`, название модели `P2Z1B-KNQ-S-D` | Значение берётся только из области дисплея. Серийный номер отбирается по формату: цифры, заглавные латинские буквы и дефис, длина ≥ 6, цифр не меньше половины. Это отсекает слова вроде `Bluetooth` и буквенные обрывки названия модели. Цифровые обрывки с дефисом (например `10-230-5` из названия модели) формат пропускает, поэтому токены с дефисом получают штраф к уверенности (раздел 7) |
| Рядом со значением единица измерения `кВт·ч` | Единицы не входят в `allowlist` и отбрасываются. В контракт не возвращаются (решение команды) |
| На экране другие элементы: значки, `АВ`, режим «Актив.эн. прям.» | Значок и надписи не должны попасть в значение, отсекаются `allowlist` и размером |

## 3. Стратегия по итерациям

| Итерация | Состав | Цель |
|---|---|---|
| 1. Baseline | Предобработка шагов 1–3 и поиск дисплея, EasyOCR в кропе дисплея (вариант A) и по полному кадру, правила выбора кандидатов из раздела 5, постобработка, уверенность | Получить первую цифру точности и время |
| 2. Улучшения | Вариант кропа B, маска бликов и inpainting, восстановление десятичной точки, запасной детектор дисплея | Закрыть самые частые ошибки из отчёта оценки |
| 3. Дообучение | Fine-tuning распознавателя EasyOCR на собранных фото | Только в случае если точность < 85% |

Предобученной модели EasyOCR достаточно для старта. Собранные фото сначала служат **оценочным набором** для подбора порогов и правил и лишь затем при необходимости обучающим.

## 4. Использование EasyOCR (`EasyOcrRecognizer`)

| Параметр | Значение | Комментарий |
|---|---|---|
| Языки `Reader` | `['en']` | Нужны цифры, точка и латинские буквы серийного номера. Кириллица пока не требуется, а набор из одного языка быстрее |
| Экземпляр | Один на процесс, создаётся при старте | Загрузка моделей занимает заметное время, не делать на запрос |
| `gpu` | из `EASYOCR_GPU` (по умолчанию `false`) | |
| Каталог моделей | `EASYOCR_MODEL_DIR`, `download_enabled=False` | Модели запекаются в образ |
| `allowlist` для значения | `0123456789.,` | Ограничивает алфавит, снимает путаницу `O/0`, `l/1` |
| `allowlist` для серийного номера | `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ-` (решение команды: буквы бывают, дефис добавить) | Заглавные латинские, кириллицы нет, модель `ru` не нужна. Буквы усиливают путаницу `O/0`, `I/1`, `S/5`, `B/8`, поэтому нужны штрихкод и проверка пользователем |
| `rotation_info` для серийного номера | `[90, 270]` | Вертикальный номер на электросчётчике. Увеличивает время, нужен замер |
| `detail` | `1` | Нужны координаты и уверенность |
| `paragraph` | `False` | Нельзя склеивать токены в абзацы |

Результат вызова приводится к `Token(text, confidence, bbox, rotation, variant)`. Координаты токена из кропа пересчитываются в систему рабочего изображения, затем в исходного.

## 5. Выбор кандидатов и постобработка (`ReadingParser`)

Постобработка по ТЗ 5.3: отсев мусорных символов, проверка формата числа, нормализация разделителей.

### 5.1. Значение (`parse_value`)

Токены берутся из кропа дисплея. Если дисплей не найден, из полного кадра с флагом `fallback_region`.

| Шаг | Правило |
|---|---|
| 1. Чистка | Удаляются пробельные символы. Оставляются только `0-9`, `.`, `,` |
| 2. Нормализация разделителя | `,` заменяется на `.` |
| 3. Проверка формата | `^\d{1,9}(\.\d{1,4})?$`. Более одного разделителя или иной формат → токен отбрасывается |
| 4. Минимальная уверенность | Токены с уверенностью ниже `MIN_TOKEN_CONFIDENCE` (0,2) отбрасываются |
| 5. Выбор | Из оставшихся берётся токен с наибольшей высотой символов (основное значение на дисплее самое крупное), при равенстве с наибольшей уверенностью |
| 6. Сохранение формы | Ведущие и хвостовые нули не удаляются: `0.0960` остаётся `0.0960` |

Если выбран токен без разделителя (только цифры), он возвращается как есть с флагом `no_decimal_point`. Формат дробной части по числу цифр не угадывается. Восстановление точки по её положению на дисплее (мелкий компонент связности между цифрами) планируется по надобности.

Если в списке нет ни одного подходящего токена, значение считается не найденным.

### 5.2. Серийный номер (`parse_serial`)

Токены берутся из полного кадра, **кроме** токенов внутри области дисплея.

| Шаг | Правило |
|---|---|
| 1. Чистка | Удаляются пробельные символы и все знаки, кроме дефиса. Буквы приводятся к верхнему регистру. Дефис в начале и в конце токена и двойные дефисы убираются |
| 2. Формат | `^(?=.{6,20}$)[0-9A-Z]+(?:-[0-9A-Z]+)*$`: цифры и заглавные латинские буквы, группы через одиночный дефис, длина 6–20 включая дефисы (допущение по длине, вопрос №1) |
| 3. Доля цифр | Среди символов без дефисов цифр не меньше половины (`SERIAL_MIN_DIGIT_RATIO=0.5`). Отсекает слова вроде `Bluetooth` и фрагменты названия модели (`KNQ`, `P2Z1B`). Короткие числа (`2025`, `230`) отсекаются длиной |
| 4. Минимальная уверенность | Токены с уверенностью ниже `MIN_TOKEN_CONFIDENCE` (0,2) отбрасываются |
| 5. Выбор | Наибольшая уверенность (с учётом штрафа за дефис, раздел 7), при равенстве большая доля цифр, затем более длинный токен |

Если токен получен из вертикального прохода (`rotation` 90 или 270), он помечается этим же флагом. Если EasyOCR режет длинный номер на два токена, ожидается проверка склейки соседних токенов на одной линии (итерация 2, по результатам оценки).

Если в списке нет ни одного подходящего токена, серийный номер считается не найденным.

### 5.3. Подстановка похожих символов

Таблица относится только к **значению показания**, где допустимы одни цифры. К серийному номеру она не применяется: буквы в нём допустимы, и замена вроде `O→0` испортила бы верный номер. Основной проход значения идёт с `allowlist`, поэтому буквы вместо цифр в нём не появляются. Подстановки нужны только как запасные, если проход выполняется без `allowlist`, и применяются лишь к токенам, где не меньше 60% символов цифры. Каждое применение даёт флаг `substituted`.

| Символ | Заменяется на |
|---|---|
| `O`, `o`, `D`, `Q` | `0` |
| `I`, `l`, `\|` | `1` |
| `Z` | `2` |
| `S` | `5` |
| `B` | `8` |

## 6. Критерии «не распознано»

`NotRecognizedError` бросается, когда после постобработки:

| Условие | `missing` |
|---|---|
| Не найден ни один допустимый кандидат значения | `reading_value` |
| Не найден ни один допустимый кандидат серийного номера | `serial_number` |
| Оба условия | оба поля |

Низкая уверенность сама по себе не ошибка: результат возвращается, а решение (показать предупреждение пользователю) принимает backend по порогу `Recognition:LowConfidenceThreshold`. Решение о том, что отсутствие одного из полей тоже ошибка, принято командой: если чего-то не видно, пользователь переснимает так, чтобы в кадр попало всё. Список `missing` нужен приложению для точной подсказки.

Тип и модель счётчика сервис не проверяет: он возвращает серийный номер и значение с экрана, а привязку к прибору при необходимости определяет backend по серийному номеру. Режим экрана электросчётчика тоже не проверяется (вопрос №3 в [README](README.md#открытые-вопросы)).

## 7. Оценка уверенности

`ConfidenceCalculator` возвращает число от 0 до 1 для каждого поля. База: уверенность EasyOCR для выбранного токена. Множители штрафов применяются последовательно:

| Условие | Множитель |
|---|---|
| Применена подстановка символов (`substituted`) | × 0,8 |
| Значение без десятичной точки (`no_decimal_point`) | × 0,7 |
| Дисплей не найден, значение взято из полного кадра (`fallback_region`) | × 0,85 |
| Серийный номер получен из повёрнутого прохода | × 0,95 |
| Серийный номер содержит дефис | × 0,9 |
| Несколько вариантов кропа дали **разные** допустимые значения | × 0,8 |
| Все варианты дали одинаковое значение | × 1,05 (не выше 1,0) |

Общая уверенность: `confidence = min(serial_confidence, value_confidence)`.

Значения множителей это отправная точка. Оценка должна быть **калиброванной**: примерно 90% ответов с уверенностью ≥ 0,9 должны быть точными. Калибровка выполняется на датасете: строится зависимость точности от уверенности, множители и порог для backend (сейчас допущение 0,8) подбираются по ней.

## 8. Возможно в дальнейшем (по надобности)

| Что | Почему |
|---|---|
| Барабанные (механические) и стрелочные счётчики | Другая задача (красные барабаны без точки, углы стрелок). Нужны данные и отдельные правила |
| Автоопределение типа прибора и профили (число знаков по модели) | Позволило бы восстанавливать точку, но требует каталога моделей |
| Штрихкод как источник серийного номера | На образце электросчётчика штрихкода нет. Может быть рассмотрено при добавлении других типов приборов |
| Проверка «тот ли это счётчик» | Не делается в CV: прибор определяется по серийному номеру на стороне backend |
| Контроль режима дисплея электросчётчика (накопленная энергия или иной параметр) | Не делается, вопрос №3 в [README](README.md#открытые-вопросы) |
