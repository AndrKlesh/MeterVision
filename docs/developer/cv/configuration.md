# Конфигурация, запуск и тестирование

## 1. Настройки

Сейчас в `app/config.py` лежат константы (`USE_MOCK` читается из окружения, остальное зашито в код). Предлагается читать всё из переменных окружения, сохранив прежние имена констант, чтобы `main.py` не ломался.

| Переменная | По умолчанию | Назначение | Статус |
|---|---|---|---|
| `USE_MOCK` | `true` | `true`: заглушка, `false`: `EasyOCREngine` | есть |
| `MAX_FILE_SIZE_MB` | `10` | Лимит размера файла. **Должен совпадать** с `Upload:MaxFileSizeMb` backend | есть (зашито в код) |
| `ALLOWED_CONTENT_TYPES` | `image/jpeg,image/png` | Допустимые типы | есть (зашито в код) |
| `MAX_IMAGE_PIXELS` | `40000000` | Защита от «распаковочных бомб» (допущение) | новое |
| `MAX_SIDE_PX` | `1600` | Длинная сторона рабочей копии | новое |
| `EASYOCR_LANGS` | `en` | Языки EasyOCR | новое |
| `EASYOCR_GPU` | `false` | Использовать GPU | новое |
| `EASYOCR_MODEL_DIR` | `/models` | Каталог моделей, загрузка из сети отключена | новое |
| `MIN_TOKEN_CONFIDENCE` | `0.2` | Порог отсева токенов | новое |
| `VALUE_DECIMALS` | `2` | Число знаков после точки (фиксированное положение точки для модели МИР С-04.10). Формат значения: `^\d{1,9}\.\d{N}$`, где `N` это `VALUE_DECIMALS` | новое |
| `SERIAL_PATTERN` | `^(?=.{6,20}$)[0-9A-Z]+(?:-[0-9A-Z]+)*$` | Формат серийного номера: цифры, заглавные латинские буквы, одиночные дефисы (допущение по длине) | новое |
| `SERIAL_MIN_DIGIT_RATIO` | `0.5` | Минимальная доля цифр в серийном номере | новое |
| `MAX_CONCURRENT_RECOGNITIONS` | `1` | Число одновременных распознаваний | новое |
| `DEBUG_SAVE_DIR` | пусто | Каталог для промежуточных изображений. Пусто: не сохранять | новое |
| `DEBUG_RETURN_RAW_TEXT` | `false` | Заполнять `raw_text` в ответе | новое |
| `LOG_LEVEL` | `INFO` | Уровень логирования | новое |

Некорректное значение (например, нечисловой лимит) должно останавливать запуск понятной ошибкой, а не приводить к скрытому поведению по умолчанию.

## 2. Локальный запуск

Заглушка (как сейчас):

```bat
cd cv
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Реальный движок (после реализации):

```bat
set USE_MOCK=false
set EASYOCR_MODEL_DIR=C:\models\easyocr
python -m uvicorn app.main:app
```

Первый запуск реального движка требует один раз скачать модели EasyOCR (нужен интернет). После этого каталог моделей можно скопировать на машину без сети. Для работы по сети добавляется `--host 0.0.0.0`, как описано в README репозитория.

## 3. Docker (эскиз)

Сервис живёт во внутренней сети docker-compose без доступа в интернет, поэтому модели должны быть внутри образа. Эскиз ниже не проверялся сборкой и служит отправной точкой для DevOps.

```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
# Для CPU желательно поставить CPU-сборку PyTorch до остальных зависимостей, образ получится заметно меньше
RUN pip install --no-cache-dir -r requirements.txt
# Скачиваем модели на этапе сборки
RUN python -c "import easyocr; easyocr.Reader(['en'], gpu=False, model_storage_directory='/models', download_enabled=True)"
COPY app ./app
ENV USE_MOCK=false EASYOCR_MODEL_DIR=/models
RUN useradd -m cv && chown -R cv /app /models
USER cv
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

В `docker-compose` сервис `cv` не публикует порт наружу, доступен backend по имени `cv` (`http://cv:8000`). Health check: `GET /health`, готов при `engine_ready=true`. Железо сервера пока неизвестно, поэтому лимиты памяти и CPU задаются после замеров на реальном движке на целевом сервере.

## 4. Логирование

Структурированный JSON в stdout (его собирает Docker). Каждый запрос логируется одной записью:

| Поле | Описание |
|---|---|
| `correlation_id` | Из заголовка `X-Correlation-Id` (его передаёт backend), иначе генерируется |
| `outcome` | `recognized`, `not_recognized`, `invalid_image`, `error` |
| `duration_ms` | Общее время, а также по этапам: `decode`, `preprocess`, `locate`, `ocr`, `postprocess` |
| `file_size`, `image_size` | Размер файла и размеры изображения |
| `serial_confidence`, `value_confidence` | Только для `recognized` |
| `display_found`, `flags` | Нашёлся ли дисплей, флаги постобработки |

Не логируются: содержимое изображений, распознанные значения и серийные номера (их можно соотнести с конкретным прибором, поэтому только в режиме `DEBUG_RETURN_RAW_TEXT`/`DEBUG_SAVE_DIR`, на разработческих стендах), пароли и токены (в CV их нет).

Метрики длительности по этапам позволят найти узкое место, если время приблизится к 4 с.

## 5. Версии и зависимости

| Что | Состояние |
|---|---|
| Python | ТЗ требует 3.11+, README репозитория пишет 3.10+, в `__pycache__` есть файлы `cpython-314`. Нужно зафиксировать одну версию в Dockerfile |
| `requirements.txt` | Уже содержит `easyocr` и `opencv-python-headless`. README перечисляет только четыре зависимости, его стоит обновить |
| PyTorch | Подтягивается как зависимость EasyOCR. Для CPU ставить CPU-сборку |
| Версии пакетов | Зафиксированы в `requirements.txt`. Совместимость и существование указанных версий проверить при первой реальной сборке |

## 6. Тестирование и оценка качества

### 6.1. Уровни

| Уровень | Что проверяет | Инструменты | Нужны ли модели |
|---|---|---|---|
| Unit: постобработка | `ReadingParser`: чистка, нормализация разделителей, формат значения и серийного номера, подстановки. Таблица «токены → ожидаемый результат», включая `50.99`, `5099` (точка восстановлена до `50.99`), `50.9` (неверное число знаков, отказ), `230` (серийный номер, отсев по длине) | pytest | Нет |
| Unit: уверенность | `ConfidenceCalculator`: штрафы, границы 0..1, `min` | pytest | Нет |
| API | Все коды ответов, формат ошибок, `/health`, сценарии заглушки (`mock_scenario`) | pytest + `TestClient` + `MockOCREngine` | Нет |
| Интеграция конвейера | Фото → результат на реальном EasyOCR для эталонных образцов | pytest (отдельная метка, медленный) | Да |
| Оценка качества | Метрики на всём датасете, раздел 6.3 | `scripts/evaluate.py` | Да |
| Интеграция с backend | Контракт, таймаут, ошибка `not_recognized` | На стороне backend, заглушка с `mock_scenario` | Нет |

Unit-тесты постобработки пишутся **до** подключения EasyOCR: им нужны только таблицы строк.

### 6.2. Датасет

Требование ТЗ: не менее 20 эталонных фото с ожидаемыми значениями. Сначала образец из раздела «Образцы» в [README](README.md#образцы), затем остальные.

Структура:

```
tests/data/
├── images/
│   ├── electric_mir_s04_001.jpg
│   └── ...
└── labels.csv
```

`labels.csv`:

| Колонка | Пример | Описание |
|---|---|---|
| `file` | `electric_mir_s04_001.jpg` | Имя файла |
| `meter_model` | `mir_s04` | Модель прибора (пока одна, колонка пригодится, когда добавятся другие) |
| `serial_number` | `50794925145054` | Эталон, сверять по оригиналу прибора, не по фото |
| `reading_value` | `50.99` | Эталон в том же формате, что возвращает сервис |
| `expected` | `ok` / `not_recognized` | Для заведомо нечитаемых кадров (размытие, закрыт дисплей) ожидается ошибка |
| `notes` | `блик справа` | Условия съёмки |

Предварительная разметка образца: серийный номер `50794925145054` (читается вертикально, перед внесением сверить с корпусом), значение `50.99`.

### 6.3. Метрики и цели

| Метрика | Определение | Цель |
|---|---|---|
| **Полная точность** (основная) | Доля фото с `expected=ok`, где **оба** поля (`reading_value` и `serial_number`) строго совпадают с эталоном | **≥ 85%** (ТЗ, критерий приёмки 7) |
| Точность значения | Доля фото, где `reading_value` строго совпадает с эталоном | Для диагностики |
| Точность серийного номера | То же для `serial_number` | Для диагностики |
| Доля `not_recognized` | Среди фото с `expected=ok` | Минимизировать. Для `expected=not_recognized` должна быть близка к 100% |
| Ошибочные «уверенные» ответы | Неверный результат с уверенностью ≥ порога | Как можно ближе к нулю: именно они вводят пользователя в заблуждение |
| Калибровка | Точность по корзинам уверенности | Монотонно растёт, на этом подбирается порог для backend |
| Время | p50 и p95 длительности запроса | p95 ≤ 4 с на целевом железе |

«Точность ≥ 85%» в ТЗ не уточнена. По решению команды считается совпадение **обоих** полей одновременно.

`scripts/evaluate.py` прогоняет `EasyOCREngine` по датасету, пишет отчёт в CSV (по каждому фото: результат, уверенность, время, ошибка) и сводную таблицу метрик. Режим `--debug` сохраняет промежуточные изображения для разбора ошибок.

### 6.4. CI

Быстрые тесты (unit и API на заглушке) запускаются в GitHub Actions на каждый PR. Медленные тесты с моделями и `evaluate.py` запускаются вручную или по расписанию, потому что требуют моделей и времени.

## 7. Сбор датасета

Фото собираются под оценку и подбор параметров, поэтому в них должно быть то, с чем сервис столкнётся у пользователей.

| Что варьировать | Зачем |
|---|---|
| Одна модель: МИР С-04.10 (электро, графический ЖК). Другие типы, возможно, позже | Покрытие области первой версии |
| Освещение и блики: с вспышкой и без, окно, лампа, прямой свет под углом | Главная причина ошибок на образцах |
| Расстояние и угол: близко, далеко, наклон 10–30° | Устойчивость поиска дисплея |
| Положение серийного номера в кадре: целиком, у края, обрезан, вне кадра | Проверка решения «нет серийного номера → ошибка» |
| Заведомо плохие кадры: размытие, закрытый дисплей, чужой предмет | Проверка корректного `not_recognized` |
| Разные телефоны | Различия камер и EXIF-ориентации |

Правила: имя файла без персональных данных; на фото не должны попадать лица, адреса и квитанции; эталонные значения сверять по самому прибору; оригиналы хранить в закрытом хранилище команды, а не в публичном репозитории (в репозиторий кладутся только обезличенные образцы, если это допустимо).
